02 화환 배송 관리 대시보드

2-1. 사용 목적

전략구매팀으로 접수되는 화환과 상조용품 배송 요청을 등록하고, 배송 진행 상태와 변경 이력을 관리하기 위한 대시보드입니다. 일반 화환 배송뿐만 아니라 장례식장 배송에 사용하는 BS 양식을 별도로 지원합니다.

2-2. 주요 기능

  • 화환 배송 요청 신규 등록 / 수정 / 삭제
  • 배송 상태 변경
  • 일반 양식과 BS 양식 구분
  • 등록일·배송일·금액·상태 기준 정렬, 상태별·조건별 필터링
  • 카카오톡 배송 요청 내용 공유
  • 엑셀 파일 업로드 / 다운로드
  • 현재 현황 서버 저장, 사용자별 변경 이력 기록
  • 다른 사용자의 선행 저장 여부 확인
  • PC 및 모바일 화면 지원

2-3. 주요 등록 항목

일반 화환 등록 시 요청일/배송일, 요청자, 수령인, 배송지, 관계, 품목, 수량, 단가 또는 금액, 배송 상태, 관리 메모 등을 입력합니다. 실제 화면의 입력 항목은 현재 배포된 코드의 등록 양식을 기준으로 확인합니다.

2-4. BS 양식 (장례식장 배송)

주요 입력 항목: 빈소, 받는 분, 고인명, 수량. BS 양식으로 등록하면 데이터에 formType: "bs" 값이 저장되고, 목록에서는 BS 표시로 일반 배송과 구분됩니다.

확인 필요고인명, 빈소, 받는 분 정보가 엑셀 다운로드 및 재업로드 과정에서도 유지되는지 확인해야 합니다.

2-5. 배송 상태

pending 배송 준비
processing 배송중
completed 배송요청 완료
issue 확인필요
cancelled 배송완료
주의화면의 한글 상태명과 내부 코드값이 다릅니다. 코드를 수정할 때는 반드시 내부 코드값을 기준으로 확인하세요. 특히 completed는 "배송이 끝났다"는 뜻이 아니라 "배송 요청이 완료되었다"는 의미로 사용됩니다.

2-6. 카카오톡 공유

배송지, 수령인, 관계, 품목, 수량 등 배송에 필요한 정보가 공유 내용에 포함됩니다. 수정 시 확인할 사항:

  • 공유 문구가 정상적으로 만들어지는지
  • 일반 양식과 BS 양식이 각각 정상 표시되는지
  • 모바일과 PC에서 공유 링크가 정상 작동하는지
  • 외부 연결 주소가 올바른지

2-7. 서버 저장 구조

GitHub 연결 Vercel 프로젝트 + Vercel Blob Storage 사용.

deliveries.json → 화환 배송 목록 logs.json → 변경 이력 API: /api/deliveries /api/logs

화면에서 입력한 데이터는 브라우저에만 저장되는 것이 아니므로, 실제 운영 데이터는 반드시 서버 저장까지 완료해야 합니다.

2-8. 저장 버전과 충돌 감지

두 사용자가 같은 데이터를 동시에 열어 둔 상태에서 서로 다른 내용을 저장하면 기존 작업을 덮어쓸 수 있어, 서버와 화면의 saveVersion을 비교해 충돌을 감지합니다.

  1. 크롬에서 데이터를 수정하고 저장
  2. 엣지는 저장 전의 이전 데이터를 열고 있음
  3. 엣지에서 그대로 저장을 시도
  4. 서버 버전과 엣지 화면의 기준 버전이 다르면 충돌 경고
  5. 최신 서버 데이터를 다시 불러온 후 내용을 확인
주의충돌 경고가 나타났는데 강제로 저장하거나 코드를 우회하면 다른 사용자의 작업을 덮어쓸 수 있습니다.

2-9. 변경 이력

신규 등록·수정·삭제·상태 변경 작업은 변경 이력에 기록되며, 최대 10개까지 유지되고 화면에서 페이지 단위로 확인할 수 있습니다. 인수인계 전 테스트 등록·저장 이력은 삭제하거나 실제 데이터와 구분되도록 정리합니다.

2-10. 운영 순서

  1. 로그인 후 서버 데이터를 새로 불러온다
  2. 기존 배송 목록과 마지막 저장 시각을 확인한다
  3. 신규 배송 요청을 등록한다
  4. 입력 내용과 배송 상태를 확인한다
  5. 필요한 경우 카카오톡으로 배송 내용을 공유한다
  6. 현황 저장을 눌러 서버에 저장한다
  7. 저장 완료 시각과 변경 이력을 확인한다
  8. 필요하면 엑셀 파일을 다운로드한다
  9. 새로고침 후 저장 내용이 유지되는지 확인한다

2-11. 주의사항

  • 화면에서 수정한 뒤 반드시 현황 저장을 해야 한다
  • 엑셀 업로드 전 기존 데이터를 다운로드해 백업한다
  • 다른 사용자가 작업 중인 경우 저장 충돌 여부를 확인한다
  • BS 양식은 일반 화환 양식과 입력 구조가 다르다
  • 테스트 데이터는 실제 운영 데이터와 섞이지 않게 한다
  • 서버 새로고침은 최신 데이터를 다시 불러오는 작업이므로 저장하지 않은 화면 내용이 사라질 수 있다
  • 코드 수정 후에는 일반 등록, BS 등록, 카카오 공유, 저장, 재접속까지 모두 테스트한다

03 구매현황 분석 대시보드

3-1. 정확한 사용 목적

품목 마스터 관리 프로그램이 아님전략구매팀의 구매·발주실적 엑셀 파일을 불러와 연도, 부서, 품목, 계약구분별 구매금액과 수량을 분석하기 위한 구매현황 분석용 대시보드입니다. 소모품 품목명 정의 업무와는 별개의 업무로 구분해야 합니다.

3-2. 업로드 가능한 파일

CSVXLSXXLS

엑셀 파일은 첫 번째 시트를 기준으로 읽습니다. CSV는 기본적으로 UTF-8로 읽으며, 정상적으로 읽히지 않는 경우 EUC-KR 방식으로 다시 처리합니다.

3-3. 필요한 엑셀 컬럼

필수있으면 함께 반영
발주일
품목명		 요청부서/부서 · 품목코드 · 발주수량 · 발주금액 · 발주단가 · 분류/품목구분 · 계약구분 · 구매업무 · 구매유형 · 계약방법

발주일이나 품목명이 없는 행은 정상 데이터로 등록되지 않습니다.

3-4. 파일 추가와 교체

기존 데이터가 있는 상태에서 새 파일을 업로드하면 추가 또는 교체 중 선택합니다. 추가 업로드 시 중복 판단 기준:

발주일 + 품목코드 + 발주수량 + 발주금액
한계같은 날짜에 동일 품목을 같은 수량·금액으로 여러 번 발주한 경우, 서로 다른 발주인데도 중복으로 제외될 수 있습니다. 업로드 후 기존/신규/최종 건수와 원본·대시보드 금액 합계를 반드시 대조하세요.

3-5. 품목 자동 분류

분류/품목구분 컬럼이 있으면 우선 사용하고, 없으면 품목명 단어 기준으로 자동 분류합니다 (시약 · 인쇄물 · 공기구비품 · 수리 · 교정 · 시험소모품). 예: Standard, Solution, Reagent, HPLC, Acid, CRM, 시약 등의 표현이 있으면 시약으로 분류될 수 있습니다. 이는 보조 기능이므로 실제 분류와 다를 수 있습니다.

3-6. 계약구분 자동 판정

사용 컬럼: 구매업무 · 계약구분 · 구매유형 · 계약유형 · 입찰구분 · 입찰방법 · 구분 · 계약방법 · 구매구분

주요 계약구분: 수의계약 · 나라장터 입찰 · 입찰-소모품 · 입찰-사업비 · 입찰-일반구매요청 · 사업비. 나라장터/조달청/G2B 문구가 있으면 나라장터 입찰로 우선 분류합니다.

임시 분류 기준 (법적 확정 기준 아님)2천만 원 이상 → 나라장터 입찰 / 2천만 원 미만 → 수의계약. 자동 분류된 계약구분은 원본 자료와 반드시 비교해야 합니다.

3-7. 데이터 품질 검사

업로드 후 자동 점검 항목: 발주일 없음/비정상 연도, 발주금액 0원, 발주수량 0, 품목코드 없음, 계약구분 미분류, 신규 처리 건수, 최종 전체 건수. 품목코드가 없는 데이터는 전체 구매금액에는 포함되지만 연도별 단가 이력 계산에는 제한이 생깁니다.

3-8. 검색 및 필터

연도 · 계약구분 · 품목 분류 · 요청부서 · 품목명 · 품목코드 · 부서명 · 최소/최대 발주금액으로 조회. 통합 검색창은 품목명·품목코드·부서명을 함께 검색합니다. 적용 필터는 배지로 표시되며, 필터 변경 시 KPI·차트·통계표·상세 목록이 함께 재계산됩니다.

3-9. 주요 KPI

  • 예산 집행률 · 총 발주금액 · 총 발주건수 · 총 발주수량 · 전년 동기 대비 증감률
  • 수의계약 / 나라장터 입찰 / 입찰-소모품 / 입찰-사업비 / 입찰-일반구매요청 / 사업비 — 각각 금액·건수·비율
  • 최다 지출 부서 · 최다 지출 품목

계약구분별 KPI 카드를 누르면 해당 필터가 자동 적용됩니다. 전년 동기 대비는 데이터상 가장 최근 연도와 전년도의 동일 월 범위를 비교합니다.

3-10. 전사 및 부서별 예산

전사 연간 예산 입력 시 집행금액·예산 잔액·초과금액·집행률을 계산합니다. 부서별 예산도 별도 입력 가능하며, 특정 부서 필터 적용 시 해당 부서 예산 기준으로 집행률이 계산됩니다.

부서별 발주건수·총 발주수량·총 발주금액·부서별 품목 구매내역 집계.

발주 상세 팝업

발주일·요청부서·품목명·품목코드·분류·계약구분·발주수량·발주단가·발주금액·동일 품목의 과거 구매 이력 확인. 동일 품목 이력은 품목코드 우선, 없으면 품목명 기준으로 조회합니다.

3-13. KPI 스냅샷

현재 필터·KPI 결과를 저장(저장일시, 필터조건, 총 발주금액/건수, 수의계약 금액, 나라장터 금액, 예산 집행률). 최대 20개까지 유지, 개별/전체 삭제 가능. 엑셀 저장 시 KPI 스냅샷 목록, 월별 추이 시트가 생성되며 월별 추이 시트에서 저장 시점별 총 발주금액과 전회 대비 증감액을 확인할 수 있습니다.

3-14. 필터 결과 엑셀 저장

현재 필터 결과만 엑셀로 저장. 구매현황 데이터(발주일·요청부서·품목명·품목코드·분류·계약구분·발주수량·발주금액)와 필터·KPI 요약(출력일시·적용 필터·총 발주건수/수량/금액·수의계약 금액·나라장터 금액·예산 집행률·전체/필터 결과 건수)이 포함됩니다.

3-15. 화면 편의 기능

섹션 개별/전체 접기·펼치기, 맨 위/아래 이동, 보드 모드(상단 메뉴·필터 숨기고 통계 화면 확대), 인쇄, PDF 저장, 모바일 대응.

3-16. 데이터 저장 방식

서버 저장 없음이 대시보드는 데이터를 서버에 저장하지 않습니다. 업로드 데이터, 전사/부서별 예산, KPI 스냅샷, 업로드 파일 정보는 모두 현재 PC · 현재 브라우저의 localStorage에 저장됩니다.
  • 같은 PC와 같은 브라우저에서만 저장 데이터가 유지된다
  • 다른 PC 또는 다른 브라우저와 데이터가 공유되지 않는다
  • 브라우저 사이트 데이터를 삭제하면 저장 데이터가 사라질 수 있다
  • 시크릿 모드에서는 데이터가 유지되지 않을 수 있다
  • 데이터가 지나치게 많으면 저장 용량을 초과할 수 있다
  • 저장 실패 경고 시 원본 파일을 다시 업로드해야 할 수 있다
  • 중요 자료는 반드시 원본 엑셀로 별도 보관한다

저장된 구매 데이터가 없으면 코드에 포함된 샘플 데이터가 표시될 수 있으므로 실제 구매실적으로 오인하지 않도록 주의합니다.

3-17. 삭제 버튼

상단 삭제 버튼은 dashboard_db(구매 데이터)만 삭제합니다. 전사 예산·부서별 예산·KPI 스냅샷·업로드 정보는 각 기능의 초기화/삭제 버튼으로 별도 삭제해야 합니다.

3-18. 운영 순서

  1. 최신 구매실적 엑셀 파일을 준비한다
  2. 원본 파일을 별도 폴더에 백업한다
  3. 대시보드에서 업로드 버튼을 누른다
  4. 기존 데이터에 추가할지 전체 교체할지 선택한다
  5. 업로드 완료 후 전체/신규 처리 건수를 확인한다
  6. 날짜 오류·금액 0원·품목코드 없음 등 품질 검사 결과를 확인한다
  7. 연도·부서·분류·계약구분 필터가 정상 생성되었는지 확인한다
  8. 대시보드 총 발주금액과 원본 엑셀 합계를 비교한다
  9. 자동 분류된 계약구분·품목 분류를 표본 확인한다
  10. 필요 시 전사/부서별 예산을 입력한다
  11. 분석 결과 확인 후 필요한 필터 결과를 엑셀로 저장한다
  12. 중요한 시점에는 KPI 스냅샷을 저장한다

04 사택 임차계약 관리 대시보드

4-1. 사용 목적

회사에서 운영하는 사택의 임차계약 정보를 관리하고 계약 종료 예정 사택을 미리 확인하기 위한 대시보드입니다. 지역별 사택 현황과 계약 기간, 보증금, 월세, 임차인, 담당자 등을 관리합니다.

4-2. 주요 기능

  • 사택 임차계약 엑셀 업로드, 전체 목록 조회
  • 신규 등록 / 수정 / 삭제
  • 지역별 필터, 임차인·주소·담당자 검색
  • 지역별 사택 수 통계
  • 최초계약일 기준 정렬
  • 계약 종료 3개월 이내 항목 표시
  • 엑셀 다운로드, 서버 현황 저장, 변경 이력 기록
  • 필터 영역 접기·펼치기, 저장 버전 확인

4-3. 주요 관리 항목

항목의미
계약 시작일현재 계약이 시작된 날짜
계약 종료일현재 계약서상의 종료 날짜
최초계약일해당 사택의 최초 계약이 시작된 날짜

지역, 주소, 임차인, 보증금, 월세, 담당자, 비고 항목도 함께 관리합니다.

주의계약 시작일 · 계약 종료일 · 최초계약일은 서로 의미가 다르므로 혼동하지 않아야 합니다.

4-4. 정렬 및 검색

기본 정렬은 최신 등록순이며, 최초계약일 기준 정렬도 가능합니다. 지역·주소·임차인·담당자 조건으로 검색·필터링할 수 있고, 필터 영역은 접기·펼치기가 가능합니다(초기 화면은 닫힌 상태일 수 있음).

4-5. 계약 만료 3개월 표시

오늘 날짜를 기준으로 앞으로 3개월 이내 계약이 종료되는 사택을 만료 예정으로 표시합니다. 판정 기준: 다음 계약 종료 예정일이 오늘과 같거나 이후이고, 오늘부터 3개월 이내일 것.

계약 종료일에 저장된 연도가 현재 연도와 맞지 않으면 월/일을 기준으로 올해 또는 다음 해의 종료 예정일을 계산합니다. 예: 기준일이 7월 16일이면 10월 16일까지 종료 예정인 계약이 포함되고, 연말에는 다음 해 1~2월 종료 계약도 정상적으로 포함되어야 합니다.

만료 예정이 이상하게 표시될 때 확인할 것계약 종료일의 실제 연도 · 월과 일 · 현재 날짜 · 날짜 형식 · 엑셀에서 날짜가 문자열로 저장되어 있는지

4-6. 지역별 통계

지역별 사택 수를 통계로 확인할 수 있으며, 통계에서는 기타 지역을 제외하도록 설정되어 있습니다. 따라서 전체 목록 건수와 지역 통계 합계가 다를 수 있으나, 기타 데이터가 삭제된 것이 아니라 통계 계산에서만 제외된 것입니다.

4-7. 서버 저장 구조

Vercel 서버 + Private Vercel Blob Storage 사용.

Blob 경로: cphg-dashboard/data.json 저장 데이터: - 사택 계약 데이터 - 변경 이력 - 업로드 원본 파일명 / 소스 파일 정보 - 서버 마지막 저장 시각 / 마지막 저장 사용자 - 저장 버전

서버 API에서는 데이터 배열이 정상적으로 전달되지 않으면 저장하지 않고 오류를 반환하도록 방어 처리가 되어 있습니다.

4-8. 저장 방식

현황 저장 버튼 → 서버에 현재 데이터 저장 → 엑셀 파일 저장 여부 선택. 엑셀 다운로드를 취소해도 서버 저장이 먼저 정상 완료되었다면 서버 데이터는 유지됩니다. 저장 후 확인할 것: 저장 완료 메시지, 마지막 저장 시각/사용자/버전, 새로고침 후 데이터 유지 여부.

4-9. 운영 순서

  1. 대시보드에 접속한다
  2. 서버의 최신 데이터를 불러온다
  3. 기존 사택 목록과 마지막 저장 시각을 확인한다
  4. 신규 등록 또는 기존 계약 정보를 수정한다
  5. 계약 종료일과 최초계약일을 다시 확인한다
  6. 만료 예정 3개월 목록에 정상 반영되는지 확인한다
  7. 현황 저장을 눌러 서버에 저장한다
  8. 필요한 경우 엑셀 파일을 다운로드한다
  9. 새로고침 후 데이터가 유지되는지 확인한다
  10. 변경 이력과 저장 시각을 확인한다

4-10. 주의사항

  • 엑셀 업로드 전 기존 서버 데이터를 백업한다
  • 빈 엑셀 파일이나 잘못 읽힌 파일을 서버에 저장하지 않는다
  • 계약 종료일과 최초계약일을 구분한다
  • 만료 예정 계산은 단순히 원본 연도만 비교하지 않는다
  • 기타 지역은 목록에는 있지만 통계에서 제외된다
  • 저장 후 반드시 새로고침하여 유지 여부를 확인한다
  • 현재 운영은 기본적으로 단일 사용자 사용을 전제로 한다
  • Blob Storage는 Private 설정을 유지한다
  • 서버 코드에서 캐시를 사용하면 새 데이터가 바로 표시되지 않을 수 있으므로 no-store 설정을 유지한다

05 ERP 소모품·시약 품목명 정의 업무

5-1. 사용 목적

기존 ERP에 등록된 불규칙한 품목명을 동일한 기준으로 정리하고, 신규 품목을 등록할 때 제조사와 제품 정보를 정확하게 식별할 수 있도록 표준 명칭을 작성하는 업무입니다. 품목명은 제조사 카탈로그, 제품 라벨, 성적서, 제품 페이지 등을 확인한 후 작성합니다.

원칙확인되지 않은 정보를 임의로 추정해서 입력하지 않습니다.

5-2. 공통 작성 원칙

  • 항목 구분자는 / 사용, 슬래시 앞뒤 공백 없음
  • 제조사명은 가능한 한 공식 영문 풀네임 사용
  • 제조사 품번은 원문 그대로 입력 (점·하이픈·영문자·숫자 임의 변경 금지)
  • 용매 표기는 제조사 표현 유지
  • 농도·순도·등급은 확인된 경우만 입력
  • 용량과 포장수량 구분
  • CAS 번호는 CAS# 번호 형식
  • 혼합 표준물질·Custom 제품은 일반적으로 CAS 번호 생략
  • 기존 등록된 동일 제품군과 순서·표현 통일
  • 제조사 공식 제품명을 불필요하게 번역·재구성하지 않음

5-3. 일반 시약

형식: 제품명/농도 또는 순도/등급/용량/제조사/제조사품번/CAS# 번호
Acetone/99.8%/GR/18L/DAEJUNG/1009-4110/CAS# 67-64-1
Hydrochloric acid/35~37%/GR/4L/DAEJUNG/4090-4104/CAS# 7647-01-0
Potassium Dichromate/≥99.98%/STD/50g/KANTO/D-32334-96-50G/CAS# 7778-50-9
Dichloromethane/99.9%/HPLC/4L/DUKSAN/577/CAS# 75-09-2

주의사항

  • 농도와 순도를 혼동하지 않는다
  • GR, EP, HPLC, STD 등 등급은 확인된 경우에만 작성
  • hydrate, anhydrous, bead 등 제품 형태를 생략하지 않는다
  • 수화물 여부에 따라 CAS 번호가 달라질 수 있다
  • 제조사 품번과 용량이 정확히 대응하는지 확인

5-4. AccuStandard 단일성분 표준물질

형식: 제품명/농도 in 용매/용량/AccuStandard/품번/CAS# 번호
Cypermethrin/1000µg/mL in MeOH/1mL/AccuStandard/P-225S-10X/CAS# 52315-07-8
Acetophenone/5.0mg/mL in Methanol/1mL/AccuStandard/AS-E0411/CAS# 98-86-2
Benomyl/100µg/mL in Acetonitrile/1mL/AccuStandard/P-104S-CN/CAS# 17804-35-2
PCB-52/35µg/mL in Isooctane/1mL/AccuStandard/C-052S/CAS# 35693-99-3
  • 제조사 표기는 "(ACCU)"가 아니라 AccuStandard로 작성
  • MeOH, CH2Cl2, Isooctane 등 제조사 용매 표기 유지
  • 단일성분 제품은 확인 가능한 경우 CAS 번호 작성
  • IS, ISTD, Surrogate 등 구분은 제품명에 유지
  • 농도 단위와 용량 혼동 주의

5-5. AccuStandard ICP 표준물질

제조사의 제품명을 가능한 한 유지합니다.

Selenium ICP-MS Standard/1000µg/mL in 2-5% HNO3/100mL/AccuStandard/ICP-MS-51N-0.1X-1/CAS# 7782-49-2
  • ICP, ICP-MS, AA 등 분석 용도 확인
  • 산 농도 범위를 제조사 표기 그대로 유지
  • 원소 단일 표준물질이면 CAS 번호 확인

5-6. AccuStandard 혼합 표준물질

형식: 제품명/성분수/농도 in 용매/용량/AccuStandard/품번
Carcinogenic Aryl Amine Mix/성분수/100µg/mL in Ethyl acetate/1mL/AccuStandard/AE-00049-R1-10X
VOC Mix/12comps/1000ppm in PT MeOH/5×1mL/AccuStandard/S-102546-02
  • 개별 CAS 번호를 품목명 뒤에 붙이지 않는다
  • 6comps, 12comps, 19comps처럼 성분 수 표시
  • 각 성분 농도가 다르면 하나의 농도로 임의 통일하지 않는다
  • 성분표와 제품 품번을 함께 확인
  • Mix, Standard, Solution 등 공식 표현 유지

5-7. AccuStandard Custom 제품

제조사에서 특정 고객 또는 시험법에 맞게 제작한 표준물질일 수 있습니다.

형식: 제품명 또는 용도/성분수/농도 in 용매/용량/AccuStandard/품번
VOC Custom Mix/19comps/100µg/mL in MeOH/2×1mL/AccuStandard/S-7686-R24-0.1X-2
Aniline Custom Standard/5000ppm in MeOH/5×1mL/AccuStandard/APP-9-012-50X
  • Custom 제품은 일반 카탈로그 검색으로 정보가 나오지 않을 수 있다
  • 라벨, 견적서, 성분표, 과거 구매기록을 함께 확인한다
  • Custom 또는 Mix 제품은 CAS 번호를 생략한다
  • 제품명·성분 수가 불명확하면 임의로 확정하지 않는다
  • 같은 품번이라도 Revision에 따라 성분·농도가 달라질 수 있다

5-8. 일반 소모품

형식: 제조사 공식 제품명/규격/포장수량/제조사/제조사품번

제품 특성에 따라 용량·크기·재질·수량 순서는 조정할 수 있지만, 같은 제품군에서는 동일한 순서를 유지합니다.

5-9. Eppendorf 피펫팁

epTIPS Standard/0.5-10mL,165mm/200tips(2×100tips)/Eppendorf/0030000765
epTIPS Box/100-5000µL,120mm(Long)/24tips/Eppendorf/0030076214

  • Box, Reload, Bulk 포장 여부 구분
  • 총 수량과 내부 포장 구성 함께 확인
  • 제조사 품번의 앞자리 0을 생략하지 않는다

Clear Glass Crimp Top Vial, Write-On Patch/20mL/PerkinElmer/N9303348

  • 바이알과 캡의 호환 여부, 포장수량, 제조사 품번
  • 비슷한 제품을 임의로 같은 품목으로 처리하지 않는다

  • 제품 시리즈와 모델 번호 함께 확인
  • 100매가 한 쌍 기준인지 낱장 기준인지 제조사 포장 확인

  • 포장수량, 호환 펌프
  • L, LL 등 품번 뒤 문자를 정확히 확인

5-13. 기타 비시약 소모품

형식: 제품명/규격 또는 크기/포장수량/제조사/제조사품번

필터, 컬럼, 바이알, 캡, 튜브, 플라스크, 실린더 등은 제품군별로 중요한 규격이 다르므로 재질·용량·직경·길이·공극 크기·연결 규격·제품 등급·포장수량·제조사 품번을 확인합니다.

5-14. 품목명 정의 작업 절차

  1. 기존 ERP 품목코드를 확인한다
  2. 현재 등록된 품목명을 확인한다
  3. 제품 라벨이나 사진에서 제조사와 품번을 찾는다
  4. 제조사 공식 카탈로그 또는 제품 페이지에서 품번을 검색한다
  5. 제품명, 농도, 순도, 등급, 용량, 포장수량을 확인한다
  6. 시약 / 표준물질 / 혼합물 / Custom / 소모품 중 유형을 구분한다
  7. 해당 유형의 명명 규칙에 맞게 품목명을 작성한다
  8. CAS 번호가 필요한 제품인지 확인한다
  9. 동일하거나 유사한 기존 ERP 품목을 검색한다
  10. 기존 제품군의 표현과 순서를 맞춘다
  11. 제조사 품번과 최종 품목명을 다시 대조한다
  12. 확인되지 않은 정보는 임의로 넣지 않고 별도 확인 대상으로 남긴다

5-15. 최종 검토 체크리스트

  • / 앞뒤에 공백이 없는가
  • 제조사명이 공식 명칭으로 작성되었는가
  • 제조사 품번이 원문과 정확히 일치하는가
  • 품번의 점과 하이픈이 정확한가
  • 용량과 포장수량을 혼동하지 않았는가
  • 농도와 순도가 정확한가
  • 제품 등급이 실제로 확인되었는가
  • 용매 표기가 제조사 자료와 일치하는가
  • 단일 표준물질에 CAS 번호가 포함되었는가
  • Mix 또는 Custom 제품에 불필요한 CAS 번호가 들어가지 않았는가
  • 성분 수가 정확한가
  • hydrate, anhydrous, IS, Surrogate 등의 구분이 유지되었는가
  • 기존 ERP의 동일 제품군 형식과 일치하는가
  • 확인되지 않은 정보를 추정하여 추가하지 않았는가

08 핵심 요약

화환 배송 대시보드는 화환 배송 요청을 등록하고 서버에 저장하는 운영용 시스템입니다.

구매현황 분석 대시보드는 구매실적 엑셀을 브라우저에 불러와 KPI, 예산, 품목, 부서, 계약구분별 통계를 확인하는 분석용 시스템이며 품목을 직접 수정하는 프로그램은 아닙니다.

사택 임차계약 대시보드는 사택 계약정보를 서버에 저장하고 계약 종료 3개월 이내 항목을 관리하는 시스템입니다.

소모품 품목명 정의 업무는 제조사 공식 자료를 확인하여 ERP 품목명을 동일한 형식으로 표준화하는 별도의 데이터 정비 업무입니다.
